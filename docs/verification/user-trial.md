# 独立上手试用

本页供使用者或编程助手按公开发行版独立上手。请先选一条路径：[新建纯 HTML/Vite Toy](../quickstart-new.md)或[把已有前端项目接入 Toy](../quickstart-existing.md)。也可把 [README 中的 Copy-Paste Prompt](../../README.md#复制给编程助手) 复制到当前项目的编程助手；它会根据项目情况使用 `toy-github` Skill 或同版本指南。

本次验收方式已于 2026-10-28 按用户要求改为两个独立 sub-agent，替代原本人试用：各自不继承实现对话，只收到 README 提示词和场景，分别新建俄罗斯方块小游戏、适配真实已有项目 `muzzle-device-lab`。这两项属于代理使用验证，不代表人类使用研究。当前运行与结论见[验收记录](acceptance.md)。

1. 按所选指南准备自己的仓库与 Toy 登录。会话只通过本机工具写入仓库 Secret，不发给他人。
2. 推送主分支，先在 Actions 里打开 **Toy 预览**，检查手机和桌面页面、资源、路由及主要交互。示例工作流会在 Summary 显示可访问的预览链接；公开仓库的链接与 Artifact 可能被他人看到。
3. 预览满意后，为**同一提交**发布 GitHub Release，查看提审运行。显示“已提交审核”只表示 B 站接受申请，不表示已上线。若愿意继续，修改页面，再做一次预览与 Release 更新。
4. 反馈所选路径、仓库/Actions 运行链接、完成到哪一步，以及遇到的卡点和文档中不清楚的句子。**不要发送会话令牌、Secret 值或完整会话文件。**

试用结果由维护者核对运行与页面后写入[验收记录](acceptance.md)，并注明执行者、所用公开版本、收到的上下文、实际阻碍和证据边界。有现成本机会话时，应如实记录安全转存和托管使用，不宣称重新完成了交互登录。
